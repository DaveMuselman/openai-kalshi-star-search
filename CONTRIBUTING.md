# Contribution and support guide

We welcome research questions, bug reports, source-format corrections and new hypotheses. Open a GitHub Issue with enough information for independent verification.

Read the [protocol](docs/PROTOCOL.md) and [data contract](docs/DATA_AND_PROVENANCE.md) first. A useful report identifies the code revision, Python/platform details, event or market ticker, expected vs observed behavior, sanitized minimal reproduction, source checksum if shareable, and resulting quality/fill decision. **Never post production credentials, account identifiers or unlicensed market recordings.**

For proposed trading hypotheses, include the exact frozen entry/exit conditions, source-admissibility filters, full trial universe, model fees/depth/latency, per-coin adverse cases, and future holdout period. A win-rate screenshot is insufficient.

Issue reviews and responses can be prepared through the connected GitHub workflow when requested or scheduled. **The project does not currently promise continuous monitoring, immediate replies or autonomous issue management.**

Please keep public contributions independent of private funded/paper executors. Version all methodological changes; retain unsuccessful results and provenance.
